Cell - название продукта (далее Cell)
Cell - единица базы данных / репозиторий, отведённый под каждого пользователя (далее клетка)
Cell body - группа из нескольких клеток, образующих общую базу данных, доступную для участников каждой клетки (далее клеточное тело)

часть 1 - общие концепции

Каждому зарегистрированному пользователю выделяется его собственная клетка фиксированного объёма. для примера 1 гигабайт.
Клетка доступна только её владельцу. Однако он может делится ею с другими пользователями.
таким образом у клетки могут быть участники со следующими ролями

Владелец - Пользователь к которому привязана клетка. Может редактировать её, редактировать участников, удалять клетку
Ревизор - Доверенное владельцем лицо (лица), в чьи обязанности входит разрешение конфликтов, которые будут возникать между авторами (например, редактирование одного и того же файла), а также модерация
Автор - Имеет право на внесение своего вклада в клетку, добавлние своих файлов, но не имеет права редактировать её
Читатель - может только читать клетку

По умолчанию клетка закрыта. Её видит только владелец. По желанию он может добавлять участников или вовсе выложить её
в открытый доступ

Группа пользователей может создавать объединения клеток, образуя клеточные тела. В данном случае клетки образуют одну большую
клетку / клеточное тело, включающее в себя входящие в неё клетки и их содержимое. Это позволяет пользователям легко объединять
свои файлы в одну общую группу. Нажав на одну ссылку, пользователю открываются все клетки в одной вкладке без необходимости
открывать каждую отдельно

часть 2 - немного подробностей

1 - Содержимое клеток
Для пользователя клетка представляет собой привычное файловое дерево, с папками и вложенными папками
С технической точки зрения все сложнее
С технической точки файлы должны находится в неком общем пространстве
Когда пользователь сохраняет файл, создаётся хеш файла и сохраняется в базу данных, которая содержит информацию о файлах.
Если таковой хеш уже имеется (то есть, в хранилище файлов такой уже есть). То новый файл не загружается, но в бд создаётся ссылка, что
данный файл привязан к некой клетке (и ко многим другим). Это сохраняет место в дата центре при загрузке популярных файлов (например, книги, установщики)

2 - клеточные тела

клеточные тела могут быть

Централизованными - тоесть иметь одного главного владельца (подходит для корпоративных решений, например для менеджера)
Децентрализованными - тоесть управление клеткой зависит от решения каждого участника тела

3 - Управление клеточным телом

Каждый пользователь в клеточном теле ответственнем за свою клетку. В любой момент он может покинуть тело
Клетка в клеточном теле автоматически открыта для всех участником тела.
Группа по умолчанию закрыта, но, по решению управляющего (главного владельца или группы участников) может стать открытой.
При этом откроется она лишь через время, а также владельцам на почту придёт уведомление о том что группа открывается. Чтобы те могли
покинуть тело если они хотят сохранять скрытность

ПОльзователи, являющиеся читателями одной клетки, не могут иметь доступа к лругой клетке, если они не являются её читателями. Даже если две клетки в одном теле
